# ねのね：参加型「見えない病気の星図」 v2

## URLと役割
- `/` : Coming Soon（展示QRの公開URLは維持）。
- `/admin/` : 現在の参加アプリ開発ページ。**パスワード保護された管理画面ではない**。公開前にトップへ差し替える予定。
- `/weekly/` : これまでの星図（累積レポート）。A4横向き印刷、最終集計日は日本時間の月曜日。
- `?week=2026-10-05` : 2026年10月5日（月）0時時点までの累積を表示。

## 参加フロー
1. 最初は何も光っていない星図を表示する。DBには353件の病名候補（厚労省指定難病348件と既存の別疾患5件）を登録している。
2. 「伝えたい想いがある」→ 疾患名を日本語または英語で検索して選択。
3. 「まだ知らない星に出会いたい」→ 関心件数が最も少ない疾患群からランダムに紹介する。未発見優先。
4. 140文字以内の任意コメントを送る（空欄でもよい）。
5. 日本時間0時で日付が切り替わるまで同じブラウザからの投稿は1回のみ。
6. 星は「伝えたい」=暖色、「知る」=寒色、両方ある場合=混合色。星をタップすると承認済みコメントだけ吹き出し表示。

## 匿名性と1日1回の限界
- WebブラウザからIMEIや電話番号などの端末固有識別子は取得できない。取得を試みない。
- `localStorage` に乱数UUIDを保存する。DBには`md5(UUID)`だけを保存し、生のトークンは記録しない。
- `UNIQUE(device_hash, entry_day)` で、同じブラウザの同じ日本時間の日付の重複をDBで抑制。
- **1人1回の本人確認ではない。** 別ブラウザ・秘密モード・ストレージ消去・端末変更で回避できる。公平性の強化が必要なら、会場限定のワンタイムコードやCAPTCHA、サーバー側制限を別途検討する。
- 健康状態／患者との関係は収集しない。公開前の案内で本名・連絡先・病歴を入力しないよう呼びかける。
- 投稿本文は`comment_approved=false`で保存され、承認後にのみ`get_public_stars()`が返す。
- `star_entries`への匿名直接 SELECT / INSERT / UPDATE / DELETE は許可していない。固定処理を行うRPCだけを公開。
- 公開RPCは大量の偽トークンによるスパム攻撃を完全には防がない。正式公開前に負荷・濫用対策を追加する。
- Google Analytics等の利用者追跡は追加していない。

## データ設計
- `disease_catalog`: 疾患名、別名、疫学情報、治療情報、出典、レビュー状況。現在353件の病名候補のみ登録。
- `star_entries`: 日付・疾患・投稿種別・承認待ちコメント・ランダムトークンのハッシュ。外部公開しない。
- `interactions`、`questions`: 旧プロトタイプのログとして保全。削除しない。
- `weekly_editorial`: 掲載可否を運営で確認した「今回の問い」等。
- `get_public_stars()`: 疾患ごとの公開済み件数と承認済みコメントの集約。
- `get_cumulative_constellation(date)`: 指定した日本時間月曜日0時**未満**の累積値。旧ログの人工テストIDは除く。

## 毎週の印刷
1. 毎週月曜日以降に`/weekly/`を開く。
2. 「最終集計日」がその月曜になっていることを確認する。累積値なので週ごとに0に戻らない。
3. 「印刷・PDF保存」で**A4横向き**を選ぶ。「背景のグラフィック」を有効にする。
4. 右上の前週・次週ボタンで過去のレポートへ戻れる。
5. 「今回の問い」は`weekly_editorial`に運営者が文章を登録し、`approved=true`とするまで空欄。
6. 掲載後は後編集で変わり得る。厳密な毎週の固定保存が必要なら印刷時PDFと集計スナップショットを別途保存する。

## 疾患データを拡充する戦略
まず病名・読み・別名・ID・出典・情報更新日を確実に整備する。日本語の起点には難病情報センターの「指定難病一覧」（2026年7月版348疾患）を使用できる。ただし**指定難病以外の希少疾患も多い**ため、後からOrphanet/OrphadataのORPHAcodeで拡張する。データ利用条件と出典表示を確認する。

採用候補の順番：
1. 病名、英語名、別名、安定識別子（可能ならORPHAcode）、公式ページURL、原データの更新日。
2. 1〜2文の正確な一般向け説明、関連疾患群と診療分野（専門監修が必要）。
3. 頻度（有病率・患者数）は**地域・年・データ元・指標の定義**とセットで保存し、無い場合は「データなし」。
4. 治療に関する情報は「根治療法の有無」など単純な真偽値を避け、疾患型・地域・時点とともに文章で管理。
5. **生存率は収集・表示しない**。疾患型・診断時期・治療歴・地域で大きく異なり、誤解を招きやすい。

自動収集は配布されている公式CSV/XML/OWLを優先し、サイトのスクレイピングは利用規約やrobots等を確認してから行う。未確認の収集データは`published=false`にしておき、重複・病名の揺れ・翻訳を整理して公開する。

## 2026-10-10 指定難病名348件の取り込み

- 2025-04時点で公開されたCC BY 4.0のCSV（[136s/intractable-disease](https://github.com/136s/intractable-disease)）から、348件の指定難病番号と病名を取り込みました。
- 番号1〜348の欠番・重複がないことを確認。公式原典は[厚生労働省・令和8年4月時点](https://www.mhlw.go.jp/stf/newpage_53881.html)。
- 2026年度版との病名表記の全件差分照合は未完了です。差分があれば訂正すること。既存病名との正規化照合で7件を統合して、新規341件、合計353件。
- `disease_catalog` に `mhlw_designation_number`, `registry_source`, `registry_edition` を追加。医学的根拠を伴う数値・治療・生存率の情報は追加していません。
- CSVと出典の詳細は `data/README.md` を参照。
- 指定難病の一覧は日本の制度上の定義であり、掲載された病気を一律に「希少疾患」と呼べるわけではありません。

## コメント公開ルール

1. コメント投稿は任意。コメントなしでも星の関心件数を更新できる。
2. 次の固定文言のみ即時公開する（文章を編集すると自由記述扱い）。
   - この病気のことをもっと知りたい
   - 少しでも多くの人に知ってほしい
   - 研究や支援が進んでほしい
   - 知るきっかけになりました
3. その他の自由記述は匿名投稿として`comment_approved=false`のまま保存し、運営が個人情報・病歴・誹謗中傷・不適切表現等を確認したうえで初めて掲載する。
4. URL、メールアドレス、一般的な電話番号パターンはDB送信段階で拒否する。ただし**NGワード検出だけでは安全性を保証できない**。
5. コンテンツ掲載はあくまで運営側の人手確認。現時点で承認専用UIは未実装（Supabase Table Editorで管理する）。
